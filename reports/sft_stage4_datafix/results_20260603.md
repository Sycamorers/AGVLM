## Benchmark Scoring Note

The initial benchmark summary reported PlantDoc out-of-label-space errors because parser label space was rebuilt from ground-truth labels only, while the prompt used `metadata.classification_label_space`. I patched benchmark sample loading and prediction re-scoring to use the per-record classification label space. This changed classification OOS from `0.0850` to `0.0`; it did not change classification accuracy or macro-F1.

## Decision

Do not promote Stage4.

Stage4 fixed the Stage3 label-space alignment issue, and the model now produces syntactically valid labels from the source-specific label spaces. However, it still does not discriminate images: classification has collapsed to one default label per source. The data-fix round improved eval loss, but the benchmark shows that loss improvement is not translating into classification behavior.

## Recommended Next Step

Stop full SFT rounds until a controlled classification-only overfit probe passes. Use a tiny balanced subset per source, run from Stage2 with higher signal on classification only, and require near-perfect greedy label accuracy on the same held-out micro set before spending another B200 run. This will separate an optimization/adapter/application problem from remaining data quality issues.
